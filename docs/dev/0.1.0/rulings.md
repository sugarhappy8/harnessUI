# 0.1.0: the decisions made while building it

Every place the plan, the spec or a review left a choice open, the build made a decision
and kept going rather than stopping to ask. Each line says what was decided, why, and what it
costs if it was wrong. They are listed in the order they were made (Task 0, then Phases A, L, B,
C and D, then the final review). A later line can amend an earlier one; where it does, it says so.

324 decisions.

- every place the plan says chrono (Tech Stack line, any chrono:: in task text) means jiff after Task 0; jiff is the one new Rust dependency, owner-approved — overrides "no new Rust or npm dependency" for jiff only — cost if wrong: small, a later task re-adds chrono and CI fails again.
- **Task 0: cannot-verify resolved — (1) cargo-deny not available locally: verified by pushing and reading CI's cargo-deny step; (2) Windows/macOS local zone detection**: accept jiff::Zoned::now() (maps Windows zone keys via its bundled tzdb, falls back to UTC if detection fails) — cost if wrong: on an unusual Windows zone, capture folder names, bench ids and report times show UTC instead of local time; (3) plan line 590 `day_start_in<Tz: chrono::TimeZone>` — Ruling: Task A3 uses jiff (`&jiff::tz::TimeZone`, local day start via jiff) — carried into A3's dispatch — cost if wrong: none beyond A3 rework.
- **Task 0: concerns**: keep jiff 0.2.46 (latest 0.2.x per brief, not yanked; parity checked on 200k instants) — cost if wrong: a regression in a 2-day-old release; fallback is 0.2.42 (Cargo.toml + lock only). Notices list jiff-static (not compiled, harmless; script requires it).
- Phase B order is B1, B4, B2, B3, B5, B6, … B14 (B2/B3 consume B4's canonical.ts) — cost if wrong: none (B4 depends only on B1).
- where scanners overlapped, one answer each: device string = L15-x-B9-device; daily-limit flag = keep would_pass (A13-x-B7-wouldPass); licence badge = L16-x-B13-licence-badge — cost if wrong: field renames in a few tasks.
